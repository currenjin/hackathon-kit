# 현장 실행표 양식

[인계 규칙](../references/delivery-handoffs.md)을 따른다. 확정된 workspace의 preparation.md 또는 runbook에 필요한 절을 사용한다. 공식 시간과 행위별 허용, 사용자 승인 밖의 작업은 보류한다.

## 시간과 경계

- 제작 시작 / 종료 / 제출 마감과 timezone / 공식 출처: 미확인
- 허용된 작업 / 보류 작업과 이유: 미확인
- 제품 위치 / 현장 기기 / 복구 경로: 미확인

## 작업별 체크포인트

각 작업마다 반복한다. 시간은 실제 행사 시간으로 정하고 고정 시간표를 강제하지 않는다.

- 작업 / 담당 (팀은 본인 확인 필요):
- 확인 시점 / 시간 예산 / 선행 작업:
- 완료 증거 (관찰할 결과와 독립 기준, 기록 경로):
- 실제 상태와 확인 시각 (계획/미실행/검증된 범위):
- 미달 시 축소·중단·대체 경로 / 자격 영향 / 결정이 필요한 사람:

최소 검토 대상은 위험 가설의 최초 확인, 첫 E2E, 조기 배포 또는 실제 실행환경 확인, 품질 검증, 발표·영상·제출 준비와 백업이다. DB·인증·두 번째 기능은 제품에 필요할 때만 포함한다. 팀만 통합 담당·합치는 시점·인수인계를 적는다.

## 채택 sponsor의 최초 호출 안내

해당 sponsor가 없으면 이유와 함께 생략한다. 미정 채택을 사용으로 가정하지 않는다. 공식 허용이 금지·unknown인 명령·prompt·입력은 사전 작성하지 않고 확인할 항목만 남긴다.

- provider / 제품 내 역할 / 채택 결정 원본:
- 공식 문서 출처 / 확인 시각 / SDK 또는 API 버전:
- 계정·인증 경로 / 환경 변수 이름 (secret 값 금지):
- 허용된 최소 입력과 실행 명령 또는 기존 제품 경로:
- 독립 기준과 정상 결과 확인 방법 (제품 출력으로 역산 금지):
- 권한 / 비용·quota / 외부 전송 데이터 / 필요한 승인:
- timeout / 재시도 한도 / 실패 시 중단 조건:
- 인증 실패·quota 부족·모델 실패 대응과 자격 영향:
- 실제 쓰기 유무 / 승인 경계 / 성공 후 readback 방법:
- 실제 실행 시각·경로·결과·마스킹한 evidence 또는 미실행 사유:

안내 작성, import 성공, local/mock 성공, 실서비스 호출 성공, 제품 E2E 성공을 구분한다. 부여 전 계정은 확인 계획만 남기고 실행 성공으로 적지 않는다. secret과 개인정보는 기록하지 않는다.

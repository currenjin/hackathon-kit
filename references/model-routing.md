# Command별 추천 모델

실제 해커톤에서 잘 맞았던 역할 분담을 정리했다. **추천이지 조건이 아니다.** 추천 모델을 쓸 수 없어도 작업은 멈추지 않는다. 쓸 수 있는 모델이 다르면 표를 자기 환경에 맞게 고친다.

시각 자산(제출 커버 이미지 등)은 이미지 생성 모델이 주도하는 편이 결과가 좋았다.

**모델 사용 가능 여부:** 행사 계정으로만 받은 모델은 행사 후 쓸 수 없을 수 있다. 그 모델이 주도·보조하던 단계는 다른 모델이 이어서 하고 "독립 검토 아님"을 적는다.

## 시작할 때 흐름

각 command는 시작하면서 아래 순서로 한 번만 확인한다.

1. 이 표에서 command의 **주도 모델**을 찾는다.
2. 지금 세션이 그 모델이면 그대로 진행한다.
3. 아니면 사용자에게 한 줄로 알리고 **바로 이어서 진행한다.** 예: "이 단계는 GPT 주도를 추천합니다. 다른 모델로 맡기실 거면 알려 주세요. 지금은 이어서 진행합니다."
4. 사용자가 "다른 모델로 할게"라고 하면 넘길 프롬프트(대상 파일·SHA·확인할 것·출력 형식·하지 말 것)를 주고, 결과가 오면 kit에 보관하고 검토한다.
5. 검토 모델도 같은 방식이다. 검토자가 없으면 주도 모델이 스스로 점검하되, 결과에 **"독립 검토 아님"**이라고 적는다.

독립성이 필요한 단계(`/demo criteria`, `/demo verify`, `/preflight`)는 만든 모델과 판정한 모델이 같으면 PASS를 주장하지 않는다. 판정 범위를 좁히거나 미확인으로 남긴다.

## 다른 모델에 넘길 때

- 넘기는 프롬프트에는 대상 파일 경로와 고정 SHA, 확인할 것, 출력 형식, **하지 말 것**(저장소 수정·제출·과장 주장)을 넣는다.
- 결과 파일은 `workspace/<event-slug>/demo-reference/` 아래에 원문 그대로 보관하고, 반영한 것과 기각한 것을 짧게 기록한다.
- 마감이 가까우면 기다릴 시한을 같이 정한다. 시한이 지나면 지금 있는 결과로 진행한다.

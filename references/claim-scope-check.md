# 문체 수정 뒤 사실 범위 재검수

`/humanize`와 `/present`에서 글투를 다듬은 다음, 렌더·게시 전에 이 검수를 한다. 문장이 자연스러워졌다는 이유로 사실까지 검증됐다고 보지 않는다.

1. **대조 기준을 고정한다.** 수정 전 문장, 고정된 expected, 실제 실행 evidence와 검토 기록의 경로·버전을 확인한다. 원문과 수정본의 수치·조건·한계를 나란히 대조한다.
2. **범위를 넓힌 표현을 찾는다.** 모든/항상/절대/각각/반드시 같은 말이 새로 들어갔거나, 특정 입력·경로에서 확인한 결과가 전체 기능의 보장으로 바뀌지 않았는지 본다. 이 표현들을 일괄 금지하지 않는다. 근거가 그 범위까지 지지하는지 확인한다.
3. **서로 다른 검증을 섞지 않는다.** 구조 검사 통과를 의미 정확성·완전성 보장으로, 단위 테스트 성공을 독립 acceptance 전체 통과로 바꾸지 않는다. 앱의 시도 횟수와 SDK 내부 요청 재시도, 허용과 실행 완료, 모델이 추출한 규칙과 원문 정책도 구분한다. 미검증 상태나 한계를 지우지 않는다.
4. **비교와 조작 설명도 확인한다.** 다른 제품 전체가 늘 틀리거나 추측한다고 단정하지 않는다. 우리 도구에서 직접 확인한 입력·조작·출력 차이를 말한다. 상태 변경, Reset, 인용 대상과 줄 번호는 실제 경로에 맞춘다.
5. **틀린 부분의 소유 경계를 지킨다.** 문체 수정 때문에 넓어진 주장은 기존 근거 범위로 돌린다. 원문 자체의 사실 오류는 지적하고, 승인 없이 사실을 새로 쓰지 않는다. 수치나 expected를 출력에 맞춰 바꾸지 않는다. 명시적으로 승인된 내용 정정은 그 범위만 반영한다.
6. **소비하는 자료까지 맞춘다.** 승인된 문장이 덱·대본·발표자 데이터·미리보기·PDF에 중복돼 있으면 해당 사본을 동기화하고 최종 렌더를 확인한다. 종료 보고에는 대조 근거와 남은 미확인을 적는다. 이 검수는 제품 PASS나 실제 발화 리허설 완료를 대신하지 않는다.
